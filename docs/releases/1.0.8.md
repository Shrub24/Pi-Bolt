Pi-Bolt 1.0.8 is a fix release: a slow local model no longer stops with "The operation timed out." when the HTTP idle
timeout is turned off or raised, `pi-bolt compile` compiles in packages that load split chunks (Cursor's SDK), and the Herdr
reporter no longer takes an error for a delivered report. Everything else is [1.0.7](1.0.7.md).

### Fixed

- **Slow models and `httpIdleTimeoutMs`** ([#206](https://github.com/opensec-git/Pi-Bolt/issues/206),
  [#216](https://github.com/opensec-git/Pi-Bolt/pull/216)): Pi-Bolt ignored the `httpIdleTimeoutMs` setting, so Bun's own
  idle timer (about 6 minutes) always applied, and a local model that took longer to start answering or paused that long
  stopped with "The operation timed out." The setting now applies as it does in Pi on Node: no response headers, or no data
  from the server, for that long fails the request, and `0` waits as long as it takes. With the default (5 minutes) nothing
  changes.
- **`pi-bolt compile` with Cursor's SDK** ([#193](https://github.com/opensec-git/Pi-Bolt/issues/193),
  [#215](https://github.com/opensec-git/Pi-Bolt/pull/215)): a package that loads its split chunks by a name it builds as it
  runs (`import("./" + name)`, as webpack builds do; `@cursor/sdk/sqlite` with `pi-cursor-sdk`) failed once compiled in, with
  "Cannot find module './19.js'". Such an import now resolves from the installed package, as when Pi loads the extension from
  its files. The fix is in the compile kit: run `pi-bolt compile` again after updating.
- **Herdr** ([#200](https://github.com/opensec-git/Pi-Bolt/issues/200),
  [#214](https://github.com/opensec-git/Pi-Bolt/pull/214)): an error from Herdr's socket counted as a delivered report, so
  the second try was skipped, and a state that failed to reach Herdr was not sent again until the state changed. Errors are
  now failures, a failed state is sent again at the next update, and nothing is reported after Pi releases the pane on quit.

### Added

- **Herdr follows `herdr:busy`** ([#201](https://github.com/opensec-git/Pi-Bolt/issues/201),
  [#214](https://github.com/opensec-git/Pi-Bolt/pull/214)): the pane shows working while
  [pi-subagents](https://github.com/nicobailon/pi-subagents) has background runs, as it already did for opensec-pi-subagents.

### Docs

- **Turning off grep and find** ([#207](https://github.com/opensec-git/Pi-Bolt/issues/207)): Pi-Bolt's built-in `grep` and
  `find` are on by default; `"defaultTools": ["-grep", "-find"]` in `~/.pi/agent/settings.json` turns them off, for an
  extension with search tools of its own.

With the default settings Pi draws the same screens and sends the same requests as 1.0.7. The release archives on the
Apple M5, 1.0.7 / **1.0.8** (medians of 15 runs; a second copy of 1.0.7 varied as much):

| | Instructions | CPU | Peak memory |
|---|---|---|---|
| `pi --version` | 52 / **52** M | 10 / **10** ms | 19 / **19** MB |
| `pi -p` (5 model turns) | 202 / **202** M | 41 / **41** ms | 52 / **52** MB |
| Interactive, 5 prompts | 603 / **603** M | 112 / **113** ms | 64 / **64** MB |

Ready to type: 37 / **36** ms.

Pi is 1.4.0. The engine and runtimes are 1.0.7's.

### Install

```bash
curl -fsSL https://pi-bolt.opensec.in/install.sh | sh
```

```powershell
irm https://pi-bolt.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://pi-bolt.opensec.in/install.ps1 | iex"
```

or `pi-bolt update`, or `npm install -g --allow-scripts=pi-bolt pi-bolt`, or `bun add -g --trust pi-bolt`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/pi-bolt`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/pi-bolt`
- mise: `github:opensec-git/Pi-Bolt` with the options in the [installation guide](https://pi-bolt.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Pi-Bolt.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Pi-Bolt`.
